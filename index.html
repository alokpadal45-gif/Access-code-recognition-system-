Validate an access code through three computational models

Every access code is checked by a Finite Automaton, a Pushdown Automaton, and a Turing Machine, one after another. Each model contributes something the one before it structurally can't, and together they decide whether a code is accepted.

Input → FA → PDA → TM → Result
Formal language

L = { w #n# wR  |  w ∈ {A,B}+,  n ∈ {0..9}+ }

An access code is a block of letters, a separator, a block of digits, a second separator, and a final block of letters. It's only valid when that final block is the exact reverse of the first. AB#123#BA qualifies because BA reverses AB; AB#123#AB does not.

What each model contributes

01

Finite Automaton

Has no memory beyond its current state, so it can only recognize patterns that don't depend on earlier input. That makes it well suited to checking the code's basic shape, but unable to verify a relationship like reversal.

02

Pushdown Automaton

Adds a stack, giving it just enough memory to remember the first letter block and compare it against the last one symbol by symbol. This is exactly the capability a Finite Automaton is missing.

03

Turing Machine

The most general of the three models. Rather than trusting the earlier stages, it re-derives the code's structure directly from the tape and performs its own independent pass before the final decision is made.

Built to show how a finite automaton, a pushdown automaton, and a Turing machine can work as one pipeline.
